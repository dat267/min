# Command Naming and cmd/ Structure Design

Date: 2026-08-02

## Goal

Improve subcommand naming in the `min` CLI and reorganize the `cmd/` folder for
maximum readability, keeping the single `cmd` package.

## Current state

Command tree (Kong-based):

```
min
├── ast scan/types/fn
├── cmd add/show/edit
├── config init/path/show/set/unset
├── dev har2openapi/openapi2go
├── init
└── version
```

`cmd/` is a flat single-package folder. Problems:

- `cmd/cmd.go` is confusingly named (cmd/cmd.go) and holds the `cmd` group.
- `har.go` / `openapi_gen.go` file names do not match the subcommand names.
- `ast.go` mixes command structs with ~350 lines of AST printing helpers.
- `dev.go` is a 6-line group definition whose help text still mentions a
  removed cURL command.
- `pkg/dev/` is orphaned dead code left over from the removed `dev http`
  (curl-to-Go) command; only its own test references it.

## Section 1: Subcommand naming

```
min
├── ast
│   ├── scan          AstScanCmd          (unchanged)
│   ├── types         AstTypesCmd         (unchanged)
│   └── function      AstFunctionCmd      ← AstFnCmd / "fn"
├── command           (was "cmd" group)
│   ├── add           CommandAddCmd       ← CmdAddCmd
│   ├── list          CommandListCmd      ← CmdShowCmd / "show"
│   └── edit          CommandEditCmd      ← CmdEditCmd
├── config            (all unchanged)
│   ├── init / path / show / set / unset
├── api               (was "dev" group)
│   ├── har2spec      Har2SpecCmd         ← Har2OpenapiCmd / "har2openapi"
│   └── client        ClientCmd           ← Openapi2GoCmd / "openapi2go"
├── init              InitCmd              (unchanged)
└── version           VersionCmd           (unchanged)
```

Details:

- `CLI` struct fields in `root.go`: `Cmd` → `Command`, `Dev` → `Api`.
- `api` group help text: `"API tools (HAR → OpenAPI, OpenAPI → Go client)"`.
- `CommandGroup` struct name stays; fields become `Add CommandAddCmd`,
  `List CommandListCmd`, `Edit CommandEditCmd`.
- `ApiCmdGroup` fields become `Har2Spec Har2SpecCmd`, `Client ClientCmd`.
- `AstCmdGroup` field `Fn` becomes `Function AstFunctionCmd`.
- Generated code header changes from `Code generated by min openapi gen.`
  to `Code generated by min api client.` (two occurrences in `client.go`).
- This is a breaking CLI change (`min cmd add` → `min command add`,
  `min dev …` → `min api …`), acceptable pre-1.0 with manual versioning.

## Section 2: cmd/ file structure

Single package `cmd`. One file per group; heavy groups split implementation
into per-command files; `ast.go` printing helpers extracted.

```
cmd/
├── root.go           CLI struct, Execute, version, config plumbing, JSONResolver   (unchanged)
├── init.go           InitCmd + project templates                                  (unchanged)
├── command.go        CommandGroup + add/list/edit + shared helpers                ← was cmd.go
├── ast.go            AstCmdGroup + scan/types/function commands + Run methods
├── ast_print.go      printing/source helpers split out of ast.go                  ← new
├── config.go         ConfigCmdGroup + 5 commands + helpers                        (unchanged)
├── api.go            ApiCmdGroup struct (Har2Spec, Client)                        ← was dev.go
├── har2spec.go       Har2SpecCmd logic: HAR structs, schema inference             ← was har.go
├── client.go         ClientCmd logic: SDK generation                              ← was openapi_gen.go
```

Tests mirror source files:

```
cmd/
├── init_test.go      init tests                          ← moved out of cmd_test.go
├── config_test.go    config tests                        ← moved out of cmd_test.go
├── command_test.go   command add/list tests              ← was cmd_test.go (init/config split out)
├── ast_test.go       ast tests (AstFnCmd → AstFunctionCmd refs)
├── har2spec_test.go  har2spec tests                      ← was har_test.go
├── client_test.go    client tests                        ← was openapi_gen_test.go
├── public_apis_test.go  end-to-end api tests (type refs updated)
└── run_test.go       (leftover template — removed, see Section 3)
```
